HiTOP-SR Module Builder

Choose the HiTOP-SR scales you need and download a questionnaire carrying only those items — a Word form to print, a Qualtrics import file, or a REDCap data dictionary.

Everything runs in your own browser. To do that the page fetches R from webr.r-wasm.org, the hitop package from jmgirard.r-universe.dev, which hands the file itself off to r2.ropensci.org, and the further R packages it needs from repo.r-wasm.org.

Item numbering

The instrument's own numbers are what this page's Qualtrics and REDCap exports use for their field names, so a paper response can be typed into a project built here without translating its number.

Item order

A shuffled form is not scored as it stands. Responses come back in the order the form printed, which is not the instrument's own; put those columns into the original HiTOP-SR order before scoring, or the scale scores come out wrong and nothing warns you.

Shuffling reaches this form only. The Qualtrics and REDCap files are never shuffled: there an item number names a collected data column.

Block and question naming

These name what the import creates in Qualtrics. Neither changes the items, their wording, or their response options. Each box starts at the package's own default; empty one and that default is used again.

Form name and required items

These name what the import creates in REDCap and how it asks for answers. Neither changes the items, their wording, or their response options. The box starts at the package's own default; empty it and that default is used again.

A download here is two files, and takes two clicks. The button below builds the questionnaire and saves it. A second button then appears, offering a small .json file listing the scales you chose and, on a shuffled Word form, the order the items were printed in. Both files are named for the build that made them — the format, whether you took every scale or a selection, and whether a Word form was shuffled — so a build differing from an earlier one in any of those three never lands on top of it. Two builds differing only in which scales you ticked do share a name, so rename one of them if you are keeping both.

Take both. Keep the .json file with the responses you collect: the hitop package reads it back with read_module() when you score the data.

These names changed on 2026-08-29. Until then a download was called hitopsr, or hitopsr-module when you had ticked only some scales, whichever format built it. Those two names are now eight, one for each format, scope and shuffle setting the page builds: hitopsr-word, hitopsr-word-shuffled, hitopsr-word-module, hitopsr-word-module-shuffled, hitopsr-qualtrics, hitopsr-qualtrics-module, hitopsr-redcap and hitopsr-redcap-module. Files you took before that date keep the names they were saved under; the rename changed nothing inside them.

The first button builds both files in this browser and saves the questionnaire; the second hands you the scoring file when you click it. The first turns on once at least one scale is ticked, and the second once a build has finished. The scoring file stays on offer until you build again, so you can take it more than once; while a build is running it switches off. That matters when the build under way is the same format as the one on offer, covers the whole instrument or a selection just as it did, and is shuffled or not just as it was: its scoring file is then headed for exactly the name the file on offer already carries, and the button being off is what stops you taking the old one under that name.
